# K8S-005 · Sistema de archivos raíz de solo lectura

| | |
|---|---|
| **Severidad** | medium |
| **Categoría** | Pod Security |
| **Modo actual** | Audit |
| **Política** | `read-only-root-filesystem` ([`policies/kubernetes/validatingpolicy-k8s-005-read-only-root-filesystem.yaml`](https://github.com/labjp-homelab/homelab-security-policies/blob/main/policies/kubernetes/validatingpolicy-k8s-005-read-only-root-filesystem.yaml)) |

## Por qué

Si el atacante no puede escribir en la raíz del contenedor, no puede dejar binarios ni modificar el código que se ejecuta. Lo que la aplicación necesite escribir va a un emptyDir montado aparte.

## Cómo cumplirla

```yaml
securityContext:
  readOnlyRootFilesystem: true
# y lo escribible, aparte:
volumeMounts:
  - name: tmp
    mountPath: /tmp
```

## Qué comprueba exactamente

Expresión CEL que evalúa Kyverno sobre cada contenedor del pod:

```
variables.containers.all(c, c.?securityContext.?readOnlyRootFilesystem.orValue(false) == true)
```
